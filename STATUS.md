_Last updated: 2026-09-21 (layer blending on the live tile path · offline download screen · local GeoTIFF import UI · field notebook persistence · Simulator run of the markup, 3D and azimuth-detent UI) · branch `main`_

GPU-shaded MapKit tiles, with spot inspection, transects, contours, hypsometric
tints and georeferenced export — extended with the micro-topography engine
(LRM, RRIM, sky-view, raking light, REM, habitation mask, viewshed, historical
map overlays, SSURGO soil hatching, directional occlusion, openness split, VRM, and DoG).

## What exists

**Engine** — harness-verified against CPU references
- `Core/Raster/Shaders/TerrainKernels.metal`: 13 micro-topography compute kernels + composite vertex/fragment (fwidth micro-contours); legacy raymarch viewshed renamed `compute_viewshed_raymarch`.
- `Core/Raster/MetalTerrainPipelineActor.swift`: zero-copy R32F binding (blit path on Simulator, bit-identical), 192 MB idle surface pool, leases, one command buffer per product, completion handlers (no `waitUntilCompleted`).
- `Core/Raster/MicroTopographyReference.swift`: CPU reference for every kernel.
- `MetalTerrainPipelineActor.renderComposite(base:modulation:blendMode:opacity:raster:window:options:thalweg:)` with the `blend_relief_layers` kernel (`Core/Raster/Shaders/TerrainKernels.metal`): composites one micro-topography product's display image over another's, in one command buffer, into a pooled surface. Blend modes are `RasterBlendMode` (`multiply`, `softLight`, `overlay`, `screen`; W3C formulas, named to avoid SwiftUI's `BlendMode`); opacity is clamped to 0...1, NaN counts as 0, and 0 returns the base bit for bit. The base's display and the modulation's display and scalar are intermediates returned to the pool when the command buffer completes; the result carries the base's scalar. `MicroTopographyReference.blend` is the CPU reference. The product-encoding switch was extracted from `render` into `encodeProduct` so both share it. Separate from `CompositeOverlays.skyViewStrength`, which multiplies sky-view into one product inside `render`. **On the live tile path (2026-09-21)**: `TerrainStyleSettings.blend` (`Core/Raster/LayerBlend.swift`: product, mode, opacity) makes `TerrainTileProvider.microPipelineImage` call `renderComposite` instead of `render` whenever the style is a micro-topography product and the layer is another product with some weight (`activeBlend`; a layer that is the style itself, zero weight, or a style that is not a micro product is ignored). Both products come from one analysis raster, so the skirt reaches as far as the farther-reaching of them (`neighbourhoodRadius(products:...)`), one options set carries both products' settings (`analysisOptions(forAll:)`: the sun lands on a raking-light or directional-occlusion layer as well as base), and relative elevation, as base or layer, gets the usual flat-plane fallback river. `renderComposite` now takes `overlays` and `outputScale` and draws contours, the habitation mask and sky-view shading over the *blended* picture at display resolution, by the same pass `render` uses (`encodeOverlayPass`, extracted from `render`, so the two cannot drift apart: at opacity 0 the composite is byte for byte `render` with the same overlays), reusing a layer that is already the product an overlay needs. UI: Settings > Terrain Layer > Blend Layer / Blend Mode / Blend Strength, shown while a micro-topography style is shown (`TerrainViewerModel.blendLayer`, `blendMode`, `blendOpacity`; the layer that is the style itself is not offered; the choice is remembered and comes back with its style; Reset Shading Defaults clears it). Defaults soft light at 70 %. A raking-light tile with a sky-view layer renders in 2.6, 3.2 and 4.1 ms warm at z18, z19 and z20 on the host GPU, against about 1 ms for the plain style. **Run in the iPad Pro 13" Simulator on 2026-09-21**: Raking Light with a Sky-View layer redraws the map (soft light lightened the picture, multiply at 70 % darkened it), 1 m contours stay drawn over the blended tiles (visible across Monks Mound's terraces), and Habitation Potential as the layer tints only where that product is opaque. Harness L7 (2 checks) and K1-K7 (31 checks): a blended tile is compared, on every pixel, with the CPU reference blend of the same two products' own tiles (four base and layer pairs, on a mound in the tile and on one across its edge), which pins both products' options and the skirt; 18 mutants run on copies of the tree were each caught, after one survivor (a skirt sized for the base alone) showed the first scene could not see a missing skirt.
- `Services/Elevation/ElevationTileCoordinator.swift`: TNM product discovery → ranged COG tiles (`prd-tnm.s3.amazonaws.com/StagedProducts/Elevation/1m`) → LZW into page-aligned storage → GPU nodata in place → Mercator resample; LRU readers/georeferences, negative TNM cache.
- `Services/Elevation/OfflineHarvestCoordinator.swift`: pre-downloads a bounding box so the map works with no signal. Enumerates the slippy-map tiles a region needs over a zoom range (tolerant of float noise on tile edges, clamped at the poles and antimeridian, counted by arithmetic so a planet-sized estimate is instant), sizes the job (`estimateFootprint`), and feeds tiles to injected `HarvestTileSource`s through a bounded task group: 4 in flight by default, never more than 6. Pause, resume and cancel (by `cancel()` or by cancelling the task that runs it), progress as an `AsyncStream<HarvestProgress>` (completed, total, failed, kB/s) and a handler. `harvest_manifest_<uuid>.json` records finished tiles, rewritten at most every 2 s and on stop, so `harvest(_:resuming:)` fetches only what is missing, failures included. Refuses a job whose estimate exceeds the disk cache, which would evict its own earliest tiles. **Called by the offline-download screen (2026-09-20)**: Settings > Local Storage & Offline Cache > Download This Area for Offline Use (`Presentation/OfflineHarvestView.swift`, decisions in `OfflineHarvestController`). It takes the area the map showed when Settings opened (1.0 km x 1.4 km in the Simulator run) with zoom levels from two below the map's to two above (steppers, 8...20), an optional USGS basemap toggle (hidden for Apple imagery, which cannot be kept), and shows the tile count and an upper-bound size. It refuses to start, with the reason in red, until the map has asked for a tile size (`provider.observedTilePixels`; the size is the device's, and a download at another would fill the disk with tiles the map never asks for) and when the job would not fit the cache it fills: the elevation and basemap caches are each checked against their own limit (500 MiB and 256 MiB, `TerrainTileProvider.elevationCacheCapacityBytes` and `HillshadeTileOverlay.harvestedTilesCapacityBytes`), not the two against one number (this closes the audit's "one number for two caches" item). While it runs it shows a progress bar (`n of N tiles`, failures, KB/s), Pause/Resume and Stop, and keeps the screen from auto-locking (`UIApplication.isIdleTimerDisabled`, released however the job ends); a job that was stopped or had tiles fail is remembered and "Continue the Last Download" resumes it from its manifest (`Application Support/OfflineHarvest`), fetching only what is missing. The controller lives on the model, so a download goes on when Settings is closed. **Run in the iPad Pro 13" Simulator on 2026-09-20**: 181 tiles at z15-18 downloaded (the estimate said 196 MB, the run stored 14 MB because most were already on disk), z15-19 was refused (637 tiles, 692 MB against 524 MB) with the reason shown, a fresh area ran with progress ("69 of 169 tiles"), paused at 107, stopped, and "Continue the Last Download" finished it ("Downloaded all 169 tiles"). Harness D1-D4 (22 checks), with 14 mutants of the controller each caught.
- `MapLayer/TerrainHarvestSource.swift`: the two sources. `TerrainElevationHarvestSource` (`TerrainTileProvider.harvestTile`) writes each padded raster under the key the renderer reads (`gridCacheKey`, which includes the tile size, so a harvest answers only the `pixels` it was made at), skips what is on disk, awaits the write rather than queueing it, keeps nothing in memory, and refuses a degraded Terrarium fallback (so outside 3DEP coverage z16+ tiles fail; z15 and below are Terrarium-native and work anywhere). `BasemapHarvestSource` keeps USGS tiles (not Apple imagery, which MapKit does not expose) in `HillshadeTileOverlay.sharedHarvestedTiles`, a separate 256 MB cache the overlay reads before the network, including for overzoomed tiles, which are cut from the harvested z13/z16 ancestor. It rejects a 200 that is not an image (a captive portal).
- `Services/Elevation/LocalGeoTIFFProvider.swift`: a user's own float GeoTIFF as an elevation source (`ElevationProviding`). Decoded by `FloatTIFFDecoder`, which now also reads the GeoKeyDirectory (projection, PixelIsArea or PixelIsPoint) and the sample layout. It keeps node-registered samples in the file's own coordinates and answers `elevation(for:targetSamples:)` by mapping each Web Mercator output node into the file (Web Mercator, UTM on WGS84 or NAD83, or plain latitude/longitude) and reading it bilinearly: exact where the grids coincide, void across a void, void beyond the file, and a request within a micro-pixel of a node returns that node so a void beside it cannot leak in. The declared no-data value, non-finite values and elevations outside -11,000...9,000 m become voids. Refused with the reason: not Float32, no georeferencing, no coordinate system, any other projection (British National Grid 27700 and Lambert-93 2154 among them), compressed, larger than 4096 px. `TerrainTileProvider.mountLocalElevation(_:)` makes it the primary source under its footprint: overlapped memory tiles are dropped, the disk cache is bypassed there, a raster made from it is never written to disk (it would outlive the file), a tile it covers only in part takes the remote source's height beyond it, and `harvestTile` still fetches the remote data. `unmountLocalElevation()` reverses it. `TerrainTileProvider.unmountLocalElevation(_:)` removes one file and leaves the others. **Import UI (2026-09-20)**: Settings > Your Elevation Data (`ViewerSettingsSheetView.localElevationSection`) has an Import GeoTIFF… button (a `.fileImporter` on the sheet itself, so it opens over the sheet), a row per imported file (name, samples, ground size) with a remove button, a progress row while a file is read and the reason a file was refused, in red. `TerrainViewerModel.importLocalElevation(from:)` holds the file's security scope across the read, decodes off the main actor, mounts it, has the map redraw once (`terrainVersion`) and flies to its footprint (with 15 % room, kept inside what MapKit can show: a raster on the 0...360 longitude convention would otherwise raise an exception there); a file with the name of one already imported replaces it, at most 4 are held (each is up to 64 MB), only one import runs at a time, and a refusal (`ImportError.explanation(forFile:)`, in words naming the file) changes nothing. Imports are held in memory and are gone when the app closes. **Run in the iPad Pro 13" Simulator**: a synthetic 30 m cone written by the app's own GeoTIFF writer, imported through a DEBUG-only environment hook (`IMPORT_LOCAL_TIFF`) that calls the same model method, flew the map to its footprint and shaded from it, with the real terrain filling in around it; the sheet listed it (256 x 256 samples, about 651 m x 667 m); the Files picker opened over the sheet and cancelling it left no message; the trash button unmounted it and the real terrain came back. Not run: choosing a file in the Files picker (the Simulator's Files storage is outside this workspace), so the picker's result handler is compiled but untested, and no import on the device. Harness G6 (unmount one) and G7 (14 checks).
- `Domain/FieldMarkup.swift`: the field notebook's data and export. `FieldWaypoint` (position, elevation, title, notes, time, photo file name) and `FieldAnnotationTrace` (ground positions, stroke width, `#RRGGBB[AA]`) are `Codable`, and `FieldMarkup.exportGeoJSON` writes an RFC 7946 FeatureCollection: waypoints as `Point` `[lon, lat, elevation?]`, traces as `LineString` `[lon, lat]`, styled with simplestyle properties (`stroke`, `stroke-width`, `stroke-opacity`, `title`, `description`), 7-decimal coordinates, NaN left out, every position validated (bad coordinate, one-point line and non-hex colour throw naming the item). Read back in the harness by MapKit's own `MKGeoJSONDecoder`.
- `MapLayer/StrokeGeoreferencer.swift`: a stroke's screen points to a ground trace through a `convert` closure (the map's `convert(_:toCoordinateFrom:)` on the device): Douglas-Peucker simplification to 1.5 points, non-finite and unplaceable points dropped. No UIKit, so the arithmetic is tested against a synthetic map of known geometry.
- `MapLayer/PencilMarkupOverlay.swift` (`PKCanvasView` wrapper: a finished stroke goes to `TerrainViewerModel.addFieldTrace` in window coordinates and the canvas is wiped), `Presentation/FieldMarkupView.swift` (pen, highlighter, hand, five colours, waypoint, undo, clear, export, done) and the wiring: a top-bar button (`toggleFieldMarkup`), the canvas over the map in `TerrainViewerView`, and `TerrainMapView.syncMarkup` drawing traces as `MKPolyline`s and waypoints as pins so they move with the map. Export goes through the existing share sheet as `LidarExplorer_Markup_<stamp>.geojson`. **Run in the iPad Pro 13" Simulator on 2026-09-20** (the canvas takes `.anyInput`, so injected touches draw): strokes stay pinned to the ground through a pan and a pinch zoom, and the polylines are back above the terrain after it is toggled off and on. Not exercised: real Apple Pencil input (pressure, tilt, hover, palm rejection), the waypoint pin, the export in QGIS.
- `Domain/FieldNotebook.swift`, `Services/Storage/FieldNotebookStore.swift` and the model's `restoreFieldMarkup`/`flushFieldMarkup`: the field notebook kept in `Documents/FieldNotebook.json` across relaunches, suspensions and terminations. The file is versioned JSON (`{"version":1,"items":[{"kind":"trace"|"waypoint",...}]}`, keys sorted, items oldest first so undo still takes the newest item after a relaunch). Reading is forgiving of one bad item (dropped and counted, an unknown kind skipped) and cleans what it keeps: a vertex, waypoint or elevation that is not a place or number goes, a colour that is not hex becomes the default ink, a width is clamped to 0.1...1000, a repeated id goes; a file that is not a notebook, or is from a later version, is refused. Writing cannot be stopped by a value that is not a number (it is written as text and cleaned on reading). The `FieldNotebookStore` actor never loses what is on disk: it writes nothing until it has read the file; a file it cannot read as a notebook (garbage, empty, cut off, wrong shape, a later version) is moved whole to `FieldNotebook.damaged-<UTC stamp>.json` before anything is written and the user is told by an alert; a file that cannot be read for now (a locked iPad) is left exactly as it is, nothing is written, and the restore is retried when the app becomes active. Saves are coalesced (the first opens a 0.5 s window, the newest notebook at its close is written, one atomic write for a burst), encoded and written off the main actor, and a failed write keeps the notebook for the next flush. The model saves after every add, undo and clear, in order (each save waits for the one before), never before the saved notebook has been read, and joins what was drawn during the read after it; the view flushes when the scene goes inactive or to the background, inside a `beginBackgroundTask` assertion (`Presentation/BackgroundWork.swift`). **Run in the Simulator on 2026-09-20**: a stroke and a waypoint survive killing the process and relaunching, and with the coalescing window stretched to 30 s (`FIELD_NOTEBOOK_SAVE_DELAY_MS`, DEBUG builds only) a stroke still waiting when Home was pressed was written by the flush (log: `flush requested: a notebook is waiting`, then `written: 3 items`) and was there after a kill and relaunch. Harness P1-P3 (37 checks).
- `Core/Geometry/TerrainMeshBuilder.swift`: an `ElevationGrid` as a triangle mesh in metres (x east, y up from the lowest sample, z south, centred; a 10 x 10 grid is 100 vertices and 486 indices). A grid over the `maxDimension` cap is resampled bilinearly, keeping corners and aspect; `zExaggeration` scales height only (base x and z are bit-identical); normals come from the exaggerated surface (central differences, one-sided at edges and voids); triangles wind counter-clockwise from above; a quad touching a void is dropped so voids are holes; uv is 0...1 west-east and north-south. No SceneKit, so it is tested host-side.
- `MapLayer/TileComposite.swift` and `TerrainTileProvider.shadedComposite(over:maxPixels:)`: the map's own shaded tile bitmaps stitched north-up into one image of a region, finer over coarser, transparent where nothing has drawn (or over an opaque `background` when one is given: the mesh's texture, which `shadedComposite` paints over neutral grey 0.92). The map's tile bitmaps are premultiplied and translucent by design (mean alpha 27 of 255 on the Cahokia scene), meant to lie over a basemap; draped bare on an opaque lit mesh they rendered near black (mean premultiplied luma 2.8, 0 % opaque pixels), found by running the 3D view in the Simulator. `Presentation/Terrain3DScene.swift` holds mesh and texture; `TerrainViewerModel.openTerrain3D()` builds it from `activeGrid` (mesh at 1x, off the main actor, cap 192) or sets `inspectorMessage`.
- `Presentation/Terrain3DOrbitView.swift` (SceneKit, iOS only): the mesh draped with the texture, one-finger orbit, pinch zoom, double-tap or button to reset, a 1x-10x exaggeration slider that scales the node rather than rebuilding. Opened from a cube button in the top bar, full screen (a sheet made a small card). Lit softly: the texture already carries the map's shading, so an ambient term (600) keeps its brightness and a directional light (500) from the north-west adds modelling. **Run in the iPad Pro 13" Simulator on 2026-09-20**: the drape and relief line up (10x exaggeration spikes the mounds where the map shades them), north is up, one-finger orbit (yaw and pitch, pitch clamped to 4.6 to 86 degrees), pinch and the reset button work. Not run: double-tap reset, the frame rate on a device.
- `Presentation/HapticDetents.swift` and `HapticFeedbackManager.swift`: haptics, with the decision apart from the hardware. `AzimuthDetents` ticks on arriving at any of the eight compass headings (within 1.5 degrees, or by passing over one between two readings when a fast drag skips its window; moving about inside a window or leaving it is silent; angles taken modulo 360). `BreakCrossingDetector` thumps when the profile scrub lands on or crosses a break of an earthwork signature (a mound's plateau edges, every ditch floor and berm crest), once per arrival. `HapticThrottle` holds each kind to one tick per 50 ms, dropping (not queueing) the rest. The `@MainActor` singleton `HapticFeedbackManager.shared` fires a selection tick or a 0.7 medium impact through them. Wired into the dock's azimuth slider (a drag ticks, the model moving the sun does not; this replaced an unthrottled impact at the four cardinals only) and the profile panel's scrub. **Run in the Simulator on 2026-09-20 with debug logging** (`Haptic: azimuth tick ...`, subsystem UI): a slow sweep of the slider ticked each of the eight headings once (a full 10 to 359 degree sweep gave 1, 2, 3, 4, 5, 6, 7 and 0, with 0 met through the 360 wrap at 358.8), a sweep of 359 degrees in 0.15 s ticked every other heading and logged the rest as dropped by the throttle, and windows a reading skipped were still ticked (170.6 for 180 in a 5-degree step). On the iPad Pro 13" the slider spans about 852 pt for 359 degrees (2.37 pt per degree), so the 3-degree window is about 7 pt, 1.4 mm. Nothing has been felt: the Simulator plays no haptics.
- `Domain/ElevationTransect.swift`: 0.5 m transects, slope/curvature, platform-mound + ditch-and-berm detection, preview profiles.
- `Domain/ProfileDecimation.swift`: Min-max bucketed decimation preserving ditches and peaks within point budgets.
- `Domain/TransectExporter.swift`: GeoJSON (RFC 7946: a 3D profile LineString plus a Point per detected earthwork signature) and CSV (RFC 4180) export of a transect analysis, georeferenced through the `GeoreferencedElevationField` the transect was sampled from. Offered from the profile panel's export menu (a CSV of the profile, or a GeoJSON of the track and its earthwork signatures) and formatted and written off the main actor, so scrubbing stays responsive (a 20,000-sample CSV stalled the main actor for 74 ms when done on it). The frame a transect was analysed in is kept with it (`TerrainViewerModel.activeTransectFrame`, origin only), so its coordinates survive later drags.
- `MapLayer/MercatorMosaicBuilder.swift`: Tiered Mercator mosaic (≤ 2048²) rasterising cached tiles coarse-to-fine for wide-area analysis up to 5 km.
- `TerrainTileProvider.analyticalRaster(for:product:options:destinationSize:)` (`MapLayer/TerrainTileOverlay.swift`): any micro-topography product over a region as a node-registered float `ElevationGrid` that `GeoTIFFWriter` exports unchanged. The mosaic is padded by the product's neighbourhood radius and only the requested window is rendered; cells are ≥ 1 m and coarsen to fit `destinationSize`. Reads the in-memory tile cache only; `.relativeElevation` returns nil (it needs a thalweg). Offered from the top-bar export menu and the settings sheet beside the raw elevation whenever the active style is a micro-topography product, using the map's own options; files are named for their content and a timestamp (`LidarExplorer_LRM_20260920-141530.tif`, `LidarExplorer_Elevation_…`).
- `MapLayer/ThalwegBuilder.swift`: River thalweg builder with geodesic densification, local minimum probing (snap to channel floor), and monotonic downstream surface descent filter.
- `Domain/SoilSurvey.swift`: SSURGO soil map unit domain model, USDA Soil Taxonomy classification (.hydricClay, .wellDrainedSandyLoam, .other), WKT/GeoJSON parsers, point-in-polygon ray casting.
- `Services/Soils/SoilDataAccessClient.swift`: USDA Soil Data Access API client with 0.01° grid-cell spatial queries, tabular JSON parser, and on-disk JSON cache.
- `MapLayer/SoilHatchOverlay.swift`: Multi-polygon vector overlay factory and MapKit renderer drawing diagonal blue hatching for hydric clay backswamps and tan cross-hatching for sandy levees.
- `MapLayer/HistoricalMap.swift` & `MapLayer/HistoricalMapOverlay.swift`: World file parser (`.pgw`, `.tfw`, `.jgw`, `.wld`), 2048 px memory-safe downsampling, Mercator tile overlay with variable opacity and vertical split wipe.

**Map & UI integration**
- `.rrim`, `.localRelief`, `.skyView`, `.rakingLight`, `.relativeElevation` render through the micro pipeline via `MapLayer/AnalysisRasterBuilder.swift`: per-product skirt, native-resolution decimation, stitching off the provider actor into zero-copy storage.
- REM tiles detrend against hand-drawn river thalweg (`TerrainTileProvider.thalweg(from:)`), falling back to a flat water plane at the visible minimum when no thalweg is drawn.
- A neighbour arriving marks already-shaded micro tiles stale; the renderer redraws them in the background and keeps the old image until the new one lands.
- Memory pressure: on a system memory warning the provider trims to what the renderer reports on screen (`TerrainTileProvider.handleMemoryPressure(visibleKeys:)`). Shaded bitmaps outside the visible tiles, the cached viewshed mosaic and half the tile cache go (never a visible tile), then idle Metal pools are purged last. The renderer supplies its visible tiles through `visibleTileKeys()`; with none registered every bitmap is dropped. CPU-fallback derivative planes are not trimmed (they exist only when the GPU kernel is unavailable). The UIKit notification observer compiles on iOS only; the harness drives `handleMemoryWarning()` directly.
- z18+ tiles stream from 3DEP COGs first (`FallbackElevationProvider`), ImageServer as fallback.
- Transect seam filter flags only resolution seams — a platform edge on a same-zoom tile seam is kept.
- Floating profile view with Elevation/Slope/Curvature picker, interactive scrub ruler, Apple Pencil gesture drawing in any mode.
- Viewshed: wide-area tiered Mercator mosaic (1m / 2.5m / 5m up to 5 km) cached on the provider and reused during observer pin movement.
- Map Styles reference panel (`?` button in top bar): searchable in-app reference covering all 16 styles and 3 overlays, with full descriptions, "How to read it", "Best for", and slider hints, plus a direct "Use This Style" action button. Renders as a side inspector panel on regular-width screens (iPad/Mac) and as a medium/large sheet on compact screens (iPhone).
- UI: horizontal scrolling style chips in bottom dock, interaction modes (explore, transect, viewshed, thalweg), settings sliders for micro-topography, historical maps importer + opacity/wipe controls, SSURGO soil hatching toggle + legend, spot callout soil readout.

### Off-screen tile culling (2026-09-18)
- [x] Cancel in-flight tile `Task`s that a pan carries outside the visible `MKMapRect`, which the generation fence cannot do (it moves only on a shading change). `TileImageStore.cancel(_:)` retires one key's claim and task; `TerrainTileOverlayRenderer.cullTiles(outsideVisible:)` drives it from `mapViewDidChangeVisibleRegion`, which fires continuously through a gesture. Because culling deliberately leaves the generation alone, claims now carry a unique `id` (`TileImageStore.Ticket`) so a cancelled task's late `finishLoad` cannot retire a fresh re-request's claim for the same key; claims culled before their task registers are remembered in `cancelledClaimIDs` so the task is cancelled on arrival rather than left running. `Task.isCancelled` guards sit ahead of shading (after the fetched raster is cached — the fetch is paid for and answers every setting) and ahead of the surface lease + stitching pass in `microPipelineImage`. Tiles within one viewport of the edge are kept, so a gesture reversal doesn't trade GPU work for a repeated fetch. Harness: `checkOffScreenTileCulling` (B11), 16 checks covering both races and the geometry.
- [x] Device-verified on iGonk Pro M5 (2026-09-18), via the Tile Activity panel: **hard flick** 765 cancelled / 899 fetched / 884 cached — culling fires hard when tiles are genuinely stranded. **Map stationary ~15 s** 0 events — culling never fires on its own, so it is not fighting MapKit's prefetcher (the one plausible thrash mode). **Realistic session** (zoom out → pan → zoom in → pan back to start) 9 cancelled / 174 fetched / 266 cached / 0 failed / 0.24 s mean fetch — ~2% cancellation during deliberate navigation, so the one-viewport margin is not over-culling. Cache hits exceeding fetches on the pan-back is the guard's placement paying off: the cancellation sits *after* the raster is cached, so returning to culled ground is served from memory rather than refetched. No margin tuning needed.
